# WeChat mini program: shared content and native school pages

Moved verbatim from AGENTS.md on 2026-11-26 to keep that file small. Record new decisions about this topic here; AGENTS.md holds only rules that apply to every task.

- `public/content/content.json`: shared content read by the WeChat mini program (`../SiDaQiHangWeChat`) from `https://sidaqihang.com/content/content.json`. Format is defined in that repo's `docs/shared-content.md`: `schemaVersion` 1, all values strings, no empty lists, `path` values must be real site routes starting with `/`, images under `/assets/`. Keep it UTF-8 without BOM. Validate with `npm run content:check -- <path>` in the mini program repo before pushing; a renamed route or moved image here must be updated in this file too. A school entry's optional `detail` (`/content/schools/<id>.json`) makes the mini program open its native school page instead of a web-view. `westSchools` lists the UK and other Western schools (same fields as `schools` plus `country`, a `westCountries` code); the mini program groups them by country and city. Burlington has its `detail` (`burlington.json`) since 2026-11-27, when mini program 1.0.2 went live.
  - `src/app/mini-program/`: native mini program school pages. `school-mini-page.ts` is the block-based format (documented in the mini program repo's `docs/school-pages.md`), and `school-pages.ts` registers one builder per school. `npm run build` runs `scripts/export-mini-program-content.cjs` after `ng build`; it bundles the builders with esbuild and writes `content/schools/<id>.json` into the build output (not into `public/`). Builders must stay pure data code (no Angular/DOM). Validate a built file with `npm run school:check -- <path or URL>` in the mini program repo. Exported pages: CIA and CPI (`cia-mini-program.ts`, `cpi-mini-program.ts`), and since 2026-11-22 EV, CPILS, CELLA Uni, CELLA Premium (`ev-mini-program.ts`, `cpils-mini-program.ts`, `cella-mini-program.ts`, all through the shared `mini-program/template-school-page.ts`, which turns a `PhSchoolProfile` into sections) and Burlington (`burlington-mini-program.ts`, text and price tables only, no `pricing`). Native pages matter because only they can be shared to WeChat Moments (a web-view cannot open there). Their quote engines `'ev'`, `'cpils'`, `'cella-uni'` and `'cella-premium'` come from `mini-program/template-quote-schools.ts` (`MINI_TEMPLATE_QUOTE_SCHOOLS`), which builds the same pricing object as each page component's `applyContentConfig` and `afterContentApplied`, plus a `priceList` the mini program uses to show the price tables as the page does; `template-quote-schools.spec.ts` (`tsconfig.mini-program.spec.json`) compares the mini program quote with the real page component for every school, with default and published content and a group. A change to one of those page components' `afterContentApplied` must be mirrored there. Their `content.json` `detail` entries (and the `schools` entries for the two CELLA campuses) were added on 2026-11-27, once mini program 1.0.2, which has these engines, was live (older versions would show raw price tables without a quote); each `pricing.defaults` is the complete default content document and `pricing.quoteEngine` (`'cia'` or `'cpi'`) picks the mini program's native quote calculator, which its `utils/nav.ts` `QUOTE_ENGINES` must list. CPI's `content.json` entry has its `detail` since 2026-11-21, because the first public mini program release (version 1.0.0) ships the `'cpi'` engine. The mini program prefers the live `/school-content/<id>/published` revision over the exported defaults. `mini-program/quote-engine.ts` is the entry the mini program bundles into `miniprogram/vendor/quote-engine.js` (`npm run quote:sync` / `quote:check` there): the CIA calculator (`cia-quote-engine.ts`, which `CiaSchoolComponent` delegates to), the CPI calculator (`cpi-page-quote.ts`, 2026-11-21), the exchange-rate rules (`services/exchange-rate-rules.ts`) and the full-detail image renderer (`components/quote-image-detailed-renderer.ts`, used by `QuoteImageDownloadButtonComponent`). Keep everything it exports pure (no Angular, DOM, storage or regex lookbehind, which older iOS WeChat cannot parse; no `structuredClone`, which the mini program runtime lacks (the EV, CPILS and CELLA content configs use `pages/philippines/copy-content-data.ts`, which keeps `undefined` keys like `structuredClone`); and no variable named `window`, because the sync check rejects the text `window.`); after changing those files, resync and release the mini program. Every school page uses one shared layout (user decision 2026-11-17): each section declares a template part `kind` (overview, fit, courses, rooms, fees, packages, features, campus, videos, calendar, policies, reviews, faq, contact), and the mini program's `utils/school-template.ts` alone decides order, titles, navigation and folding; builders never choose layout. Every builder ends with `contactSection()` from `shared-sections.ts`, which reuses `components/sida-why-content.ts` (the text of the shared `SidaWhySectionComponent`) and `components/sida-consultants.ts` (the shared consultant list, also used by the CIA page), so guarantee and consultant changes are made once. Room photos use a `rooms` block whose `codes` match the room `code` values in the published content so the mini program can show each room type with its live price.
