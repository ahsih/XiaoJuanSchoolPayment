# SEO, prerendering and brand facts

Moved verbatim from AGENTS.md on 2026-11-26 to keep that file small. Record new decisions about this topic here; AGENTS.md holds only rules that apply to every task.

- `src/app/pages/about-sida/about/brand-facts.ts`: the user's 思达启航品牌事实卡 (2026-11-19), the unified public wording for the brand. One pure module renders the 关于思达启航 page at `/about-sida/about` (styles in `public/assets/about-sida/brand-facts.css`), the full Organization/FAQPage JSON-LD and `/llms.txt`; the build prerenders the page (see the prerendering note under Conventions) so the text is visible in the page source. Change brand facts there only. `BRAND_FORBIDDEN_PHRASES` (98%, 5000+, 成功率, 录取无忧, 分公司, 办公室, 第一, 唯一, 首选, 最好, 思达教育…) fails the build if they appear on that page or in `llms.txt`; the fact card also forbids student counts, partner-school counts, testimonials in a student's name and unprovable technology claims anywhere on the site. Use 驻点人员 for the Philippines/UK/Hangzhou staff, never offices or branches. `llms.txt` is served with a UTF-8 charset by `Program.cs`. Always write the brand in full as 思达启航, never 思达 or the former name 思达游学 (user decision 2026-11-20; the CIA page is excluded until the user unlocks it). Saved school content may still use the short name, so `SchoolContentService.getPublished` passes every published revision except CIA through `services/brand-name.ts`. Server seed fee names such as 思达折扣 are lookup keys for the insert-only seed and stay unchanged.

- Server-rendered SEO tags: Baidu and WeChat link previews usually do not run JavaScript, so previously every URL's raw HTML carried the homepage title. `npm run build` now runs `scripts/export-seo-pages.cjs` after `ng build`. The script evaluates the pure data exported by `seo.service.ts` (`SEO_PAGES`, `SECTION_SEO`, `DEFAULT_SEO`, `seoTitle`) and writes `seo-pages.json` next to the built `index.html`; it fails the build if an entry lacks a title or description. The server's `Services/Seo/SpaSeoHtmlRenderer.cs` (the SPA fallback in `Program.cs`) strips the built-in title/description/keywords/og/twitter/canonical tags and inserts the requested route's own, using the same exact-path → section-prefix → default lookup and trailing-slash rule as the client. Keep `seo.service.ts` data free of Angular/DOM use. Missing `seo-pages.json` serves the plain `index.html`. `/` also goes through this renderer: endpoint routing picks the SPA fallback before the static `index.html`, so a change that assumes `/` is served as a static file has no effect there. Since 2026-11-20 the same script also writes each exact `SEO_PAGES` route's schema.org JSON-LD (`buildSeoStructuredData`, which the browser `SeoService` also uses, always with the canonical `https://sidaqihang.com` origin) into `seo-pages.json`, injects the home page's JSON-LD into the built `index.html`, and writes `llms.txt`; the renderer replaces the `<script id="seo-json-ld">` per route. Page bodies are prerendered at build time (2026-11-22, after an outside check found 0 Chinese body characters in the source of the home, contact and why-Philippines pages): see the next note. The manual server `sitemapEntries` list must contain every real school route and no redirect-only route. `index.html` carries the `baidu-site-verification` meta tag that proves ownership of `https://sidaqihang.com` in 百度搜索资源平台; never remove it, and never add `baidu-site-verification` to the renderer's stripped-tag pattern.
- Build-time prerendering (2026-11-22): AI tools and most crawlers read only the page source, so the production `ng build` renders every route in `xiaojuanschoolpayment.client/prerender-routes.txt` once in Node (Angular's own prerendering: `server`, `ssr: true` and `prerender` in the production configuration of `angular.json`, `src/main.server.ts`, `src/app/app.module.server.ts`, and the packages `@angular/ssr` and `@angular/platform-server` pinned to the installed Angular version). The site is still a client-rendered app: there is no SSR server and no hydration; Angular replaces the prerendered body when it starts, so the visible page is unchanged. `index.html` becomes the prerendered home page (also kept in `seo-pages.json`, which is what `/` serves) and `index.csr.html` the empty shell. `scripts/export-seo-pages.cjs` checks every prerendered page and moves it into `seo-pages.json` (`prerendered`, about 3.5 MB), deleting the `<route>/index.html` folders because `FindStaticSiteIndex` would serve such a folder as a separate static site; `SpaSeoHtmlRenderer` serves a route's prerendered page, or the shell, with that route's own tags. The build fails if a page throws while prerendering (the server module's error handler writes a `sida-prerender-error` meta tag) or has fewer than 100 Chinese characters in its `<main>`. While `ng build` prerenders these pages there is no API: every HTTP request fails at once, so pages show their no-data fallback. Rules for listed pages: no `window`, `localStorage`, `navigator` or direct `document` use in constructors, field initialisers, `ngOnInit` or `ngAfterViewInit` without `isPlatformBrowser(inject(PLATFORM_ID))` (see `ContactComponent`), and no never-ending `setInterval` or timer during the first render, which makes the build time out after 30 seconds. Listed so far: home, why-Philippines, the city and school-directory pages, cost, FAQ, offers, recommendations, the Philippines guide, the airport-pickup guide, the four CIA student stories, 关于思达启航, contact and the student-feedback pages. School pages (2026-11-23): every school detail page and `/price-compare` is in `prerender-school-routes.txt` instead, which `scripts/prerender-school-pages.cjs` renders after `ng build` with the same server bundle (`ssr: true` writes it to `dist/.../server`), one worker and a 60-second limit per page. Their prices come from published content revisions and the database, so the site's own GET requests go to the live site named by `SIDA_PRERENDER_API_ORIGIN` (the Dockerfile sets `https://sidaqihang.com`; unset or unreachable means no school page is prerendered); other sites, such as the exchange-rate API, are never called, so the quote shows rates as pending until the browser loads them. Each page records the school IDs named in its requests (`?schoolId=`, `/school-content/<id>/…`) and its render time, stored as `prerenderedSchools` in `seo-pages.json`; `SpaSeoHtmlRenderer` serves the page only while `Services/Seo/SchoolDataFreshness.cs` reports none of those schools changed since (latest published revision, or course/room/fee/note/photo `LastUpdated`, read at most every 10 seconds; an unreadable database counts as changed), otherwise the shell, so the source never shows an old price; the next deploy renders it again. A school page that throws, times out, fails to load its data or has under 100 Chinese characters in `<main>` is left out with a warning instead of failing the build. Keep the same browser-only rules in school pages and the shared services they use (`SchoolService` reads the token through a guard, `ExchangeRateService` refreshes hourly only in the browser). Verify a change with `SIDA_PRERENDER_API_ORIGIN=https://sidaqihang.com npm run build` and read its warnings; the live check is “查看网页源代码” and Ctrl+F for a sentence from the page body.
